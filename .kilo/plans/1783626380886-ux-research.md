# UX Research — Retention, Delight, and Product Gaps (SLAMS)

Research basis: established product/UX principles (hara-hachi, progressive disclosure, micro-rewards,
flow state, perceived performance, self-determination theory: autonomy/mastery/relatedness, the
"aha → habit" loop, Nielsen heuristics, gameful design / Octalysis) applied to a campus attendance app.

═══════════════════════════════════════════════════════════════════════════════════
## 1. What makes users stay (and how SLAMS applies it)
═══════════════════════════════════════════════════════════════════════════════════

A. Perceived performance & instant feedback
   - Skeleton loaders + optimistic UI make the app "feel" instant even on slow links.
   - Apply: skeleton shells on all suspense routes; optimistic toast on sign-in; button busy states.
   - SLAMS already has toasts + spinners; add skeletons + prefetch on hover of course cards.

B. Micro-rewards & variable positive feedback (dopamine loops)
   - Confetti on success, animated count-ups, progress rings that "snap" to new values.
   - Apply: confetti on student sign-in AND lecturer session end (different palettes per the request);
     AnimatedNumber already exists — extend to progress rings.

C. Mastery & progress visibility (self-determination: mastery)
   - People return when they can see themselves improving. Attendance % is the core metric.
   - Apply: milestone messages (first sign-in, perfect week, 100% course, streak, comeback, at-risk
     warning). "Streak" counters create a reason to return tomorrow.

D. Autonomy & control
   - Let users personalize (theme already exists; add brandable accent + editable profile).
   - Apply: settings page editable name/avatar; admin branding page.

E. Relatedness / social proof
   - Landing testimonials, class leaderboards (opt-in), "42/54 signed in" live counters.
   - Apply: live sign-in counter already present in session view — keep & animate; optional
     course leaderboard (privacy-aware, off by default).

F. Reduced friction (the "aha → habit" loop)
   - One-tap sign-in (QR scan) is already the killer feature. Reduce steps further:
     auto-open camera on /student/attend; remember last code; deep-link from email/notification.
   - Apply: auto-start scanner option; "sign in to another" flow already good — add confetti.

G. Delight & emotional design (Aarron Walter's "emotional design")
   - Personality in copy, playful empty states, celebratory moments, tasteful motion.
   - Apply: illustrated empty states (EmptyState component, currently unused), milestone toasts with
     emoji, course/track icons so lists aren't "plain text", softer not-so-serious visual tone.

H. Consistency & trust (Nielsen)
   - Predictable navigation, clear error recovery, no dark patterns.
   - Apply: uniform empty states, real (not fake) marketing stats, honest QR-claim (fix or reword).

I. Accessibility & comfort
   - `prefers-reduced-motion` support; sufficient contrast; keyboard nav; aria-labels.
   - Apply: global reduced-motion media query; audit gradient-text contrast; aria on icon buttons.

J. "Don't look so official/serious"
   - Soften the UI: rounded shapes (already 2xl), friendly illustrations, gradient accents, gentle
     motion, human copy. Avoid pure enterprise grey. Keep professional but warm.

## 2. Concrete delight features to implement (the request's "make it come alive")
═══════════════════════════════════════════════════════════════════════════════════

- Course & track icons: each course/department gets an icon + color → gradient tile (not plain text).
- Confetti: student sign-in (success burst, teal/green); lecturer session end & milestones (gold/confetti
  with emoji). Two distinct presets.
- Milestone messages (implement ALL of these):
  1. First sign-in ever (welcome aboard)
  2. First sign-in for a course
  3. Perfect week (attended 100% of sessions that week)
  4. 100% course attendance
  5. Streak N (3/7/14/30 consecutive sessions)
  6. At-risk warning (dropped below threshold)
  7. Comeback (was at-risk, now back above)
  8. Session closed (lecturer) — celebration of N students reached
- Motion system: entrance stagger, hover lift (exists), scale-in on results, shimmer on loaders,
  page transition wrapper, pulse-ring on live QR (exists).
- Live counters animate; progress rings; celebratory banners.

## 3. Gaps / flaws vs. the app's actual purpose (attendance integrity + adoption)
═══════════════════════════════════════════════════════════════════════════════════

Purpose = "secure, digital, fraud-resistant lecture attendance that saves time and gives real insights."

FLAW 1 — QR/code claim is currently false.
  Marketing says screenshots become useless; in reality the 6-digit code is valid for the whole window
  and a screenshot of the number works. Either enforce one-time/rotating codes or reword copy.
  (Rotation adds complexity; minimal honest fix = reword + add short auto-expire + optional
  per-sign-in single-use. Recommend: reword now, add rotation later.)

FLAW 2 — No student live-session discovery.
  A student only signs in if they already know the code. Forgotten code = missed attendance.
  Add "Active sessions for my courses" tile on student dashboard pulling open sessions.

FLAW 3 — Weak account security & no recovery.
  No forgot-password, no email verify, admin forms prefill "password123". Blocks real institutional use.

FLAW 4 — No excused-absence / justification path.
  Life happens; all-or-nothing % punishes illness. Add optional "excused" flag on records (lecturer/admin).

FLAW 5 — No proactive low-attendance alerts.
  The system knows who's at risk but never tells the student/lecturer until they dig in. Add alerts
  (in-app + optional email) when a student crosses the at-risk threshold.

FLAW 6 — Reporting is per-course only.
  Admins/depts can't get a faculty or department roll-up without opening each course. Use existing
  `facultyReport` server fn + add department filter & export.

FLAW 7 — Data persistence & multi-instance.
  In-memory seed resets on deploy/preview; no migration story for D1. Real deployments will lose data.
  Needs explicit persistence + seeding strategy + optional reset control.

FLAW 8 — No audit log / accountability.
  Admin creates/deletes/enrolls with no trace. Add lightweight action log.

FLAW 9 — No scale guards.
  No search/filter/pagination on large user lists; no rate-limit on submit; checkbox enrollment is
  O(n) DOM for big cohorts.

FLAW 10 — Accessibility & motion comfort gaps.
  Gradient text contrast, missing aria-labels on some icon buttons, no reduced-motion respect.

FLAW 11 — Fake marketing stats on landing.
  "Fraud blocked 100%" etc. are invented. Either wire to real `adminOverview` aggregates or hide via
  `siteSettings.showFakeStats`.

FLAW 12 — No tests / CI.
  Only `npm run build` gates quality. Add at least smoke tests for critical server fns (auth, submit).

## 4. Prioritization lens (for the implementation plan)
═══════════════════════════════════════════════════════════════════════════════════
P0 (trust/integrity + the explicit ask): course/track icons, confetti (both), milestone messages,
   threshold-to-settings, remove hardcoded password123 prefill, honest QR copy.
P1 (delight/polish): skeleton loaders, page transitions, empty-state unification, reduced-motion,
   animation system, live session discovery tile, animated counters/rings.
P2 (admin controllability): branding/site-settings page driving marquee/testimonials/institution name/
   demo accounts/threshold/primary color.
P3 (closing real gaps): forgot-password stub, excused absences, low-attendance alerts, department
   report export, audit log, search/filter on lists, tests/CI, persistence story.
