# SLAMS Frontend Audit — Static / Mock / Hardcoded + Incomplete Parts

Scope: every user-facing screen in `src/routes/**`, shared components in `src/components/**`,
and the data contract in `src/lib/api.functions.ts` + `src/lib/db.server.ts`.
Goal: catalog what is hardcoded/mock today, what could be driven by the backend/admin panel,
and what features/flows are stubbed, missing, or incomplete. This feeds the UI-livening plan.

Legend:
- [STATIC] hardcoded literal that should be backend/admin configurable
- [MOCK] fake demo data baked into the UI
- [INCOMPLETE] feature/flow partially built or missing
- [GAP] missing capability that undermines the product's purpose

## PART A — Static / Mock / Hardcoded → candidates for backend/admin control
═══════════════════════════════════════════════════════════════════════════════════

### Landing page (`src/routes/index.tsx`)
- [MOCK] `LogoMarquee` faculty list is a fixed JS array: "Faculty of Science", "Faculty of Engineering",
  "Faculty of Arts", "Business School", "College of Medicine", "School of Computing" (lines 200-207).
  Should be a backend `siteSettings.marqueeItems` array editable from admin.
- [MOCK] `Testimonials` are 3 hardcoded quotes/names/roles (lines 337-341). Should come from
  `siteSettings.testimonials` (admin-managed, can be empty).
- [MOCK] Hero stat numbers "Sign-in time ~4s", "Fraud blocked 100%", "Report formats PDF·XLSX"
  (lines 121-138). The first two are invented marketing claims; should be toggled/hidden via
  `siteSettings.showFakeStats` or replaced by real aggregate stats from `adminOverview`.
- [MOCK/STATIC] Hero "live session" preview (lines 141-193) shows fake course "CSC 305 · Data Structures",
  fake QR grid, fake code "483 902", fake "42 / 54". This is decorative only — acceptable as illustration,
  BUT the QR should ideally render a real scannable demo link so it's not misleading.
- [STATIC] `password: password123` demo hint (line 398) and CTA demo accounts (lines 390-400) are
  hardcoded. Should read `demoAccountsEnabled` + `demoPassword` from `siteSettings`.
- [STATIC] Institution name "SLAMS" / tagline appears in Header, Footer, CTA, Login. Should be
  `siteSettings.institutionName` so an admin can rebrand.

### Login (`src/routes/login.tsx`)
- [MOCK] Demo autofill buttons hardcode `${r}@slams.edu` + `password123` (lines 54-57, 90, 129).
  Should use `siteSettings.demoAccountsEnabled`, `demoPassword`, and a configurable demo-email domain.
- [STATIC] "Demo password for all roles: password123" (line 129) — same as above.

### Admin — Students / Lecturers / Courses create forms
- [STATIC/SECURITY] New-student and new-lecturer forms prefill `password: "password123"`
  (`admin.students.tsx` line 43 & 74, `admin.lecturers.tsx` line 42 & 66). This is both a hardcoded
  value and a security smell (auto-generating weak passwords). Should either generate a random temp
  password shown once, or leave blank and force set-later. Driven by policy, not a literal.

### Attendance threshold (the "70%" rule)
- [STATIC] `70` is hardcoded in FOUR places as the at-risk / fail boundary:
  - `student.index.tsx` line 19 (`c.percentage < 70`) and line 35 hint text "At risk (< 70%)".
  - `admin.reports.tsx` line 96 (`s.percentage < 70`).
  - `lecturer.courses.$courseId.tsx` line 178 (`s.percentage < 70`).
  Should be a single `siteSettings.atRiskThreshold` (default 70) applied everywhere.

### Course & Department visual identity
- [STATIC] Every course/lecturer-card/department uses the same `BookOpen` icon (e.g. `admin.courses.tsx`
  line 106, `lecturer.index.tsx` line 40, `lecturer.courses.tsx` line 29, `student.index.tsx` line 44-45
  uses no icon, `student/courses/$courseId.tsx` line 51 uses `BookOpen`). No per-course or per-track icon.
  `Course`/`Department` models have no `icon`/`color`/`category` field. This is the "plain text" problem
  the user called out. → Add `icon` + `color` (+ optional `category`/"track") to models, admin-editable.

### Admin overview chart & recent sessions
- [STATIC] Chart gradient colors are hardcoded `oklch(0.44 0.11 165)` (admin.index.tsx lines 41-51).
  Fine as brand default, but should derive from `siteSettings.primaryColor` if branding is added.
- [OK] Data itself (counts, weeklyAttendance, recentSessions) is real, from `adminOverview`.

### Reports / Exports
- [OK functionally] Real data via `courseReport`/`exportPDF`/`exportExcel`.
- [STATIC] Only per-course reports. No department/faculty roll-up export (gap, see Part B).

### Student dashboard
- [STATIC] "At risk (< 70%)" label hardcoded (see threshold above).
- [INCOMPLETE] No "active live sessions for my courses" surfaced — student must already know the code.
  (Gap: live session discovery.)

### Settings (`src/routes/settings.tsx`)
- [INCOMPLETE] Only password change + read-only profile. No ability to edit display name,
  department, level, or upload avatar. Profile is effectively read-only beyond password.

## PART B — Incomplete / Missing features, flows, dashboards, components
═══════════════════════════════════════════════════════════════════════════════════

### Auth & account
- [GAP] No "Forgot password" / reset flow (only `changePassword`).
- [GAP] No email verification on signup.
- [GAP] No account self-service profile editing (name/dept/avatar) — settings.tsx limited to password.
- [GAP] No admin "edit user" dialog though `updateStudent`/`updateLecturer` server fns exist and were
  just fixed in db.server — the admin UI never calls them. (Incomplete wiring.)
- [GAP] No bulk import (CSV) for students/lecturers — only manual create + checkbox enrollment.
- [GAP] No search/filter/pagination on Students, Lecturers, Courses tables (lists are raw maps).

### Attendance flow
- [GAP] QR code is just a deep link `/student/attend?code=XXXX` (lecturer.sessions.$sessionId.tsx line 43).
  It is not cryptographically bound; a screenshot of the *code number* works, which is the real gate.
  The marketing claim "screenshots become useless" (index.tsx line 230) is currently false — codes are
  reusable for the whole session window. Needs rotation or one-time-use enforcement to match the claim.
- [GAP] No rate-limiting / abuse protection on `submitAttendance`.
- [GAP] GPS geofence is trivially spoofable (client sends lat/lng); no server-side validation strength.
- [GAP] Student has no way to see which of their courses currently have a LIVE session (discovery).
- [GAP] No "excused absence" / justification flow; missed = missed.

### Dashboards & analytics
- [GAP] No department-level or faculty-level report/export (only per-course + adminOverview counts).
- [GAP] Admin overview lacks: engagement/retention metrics, low-attendance student watchlist,
  per-department breakdown beyond counts.
- [GAP] No time-range selector on the weekly chart (hardcoded last 7 days).
- [INCOMPLETE] Student course detail (`student/courses/$courseId.tsx`) is basic: shows sessions list but
  no progress celebration, no milestone messages, no confetti, no course icon, no session QR/code,
  no "what you missed" summary.

### Gamification / delight (explicitly requested)
- [GAP] No confetti on student sign-in success (student.attend.tsx shows a checkmark only).
- [GAP] No confetti / celebration when lecturer ends a session or hits a milestone.
- [GAP] No milestone messages (first sign-in, perfect week, 100% course, streak, at-risk warning, comeback).
- [GAP] No attendance streaks, badges, or progress celebrations anywhere.

### Branding / admin controllability
- [GAP] No admin "Branding / Site settings" page to control institution name, threshold, marquee,
  testimonials, demo accounts, accent color. All currently hardcoded (see Part A).
- [GAP] Course/Department icons & colors not editable (models lack the fields).

### Polish / UX completeness
- [GAP] `EmptyState` component exists but is unused on most screens (students w/ 0 courses uses inline
  dashed box; history uses inline; reports uses inline). Inconsistent empty states.
- [GAP] No skeleton loaders for suspense routes (brief flash of nothing). `useSuspenseQuery` throws to
  a boundary; no pretty loading shell.
- [GAP] No page transitions between routes (instant swap).
- [GAP] `prefers-reduced-motion` not universally respected (animations run regardless).
- [GAP] Accessibility: gradient text (`gradient-text`) can fail contrast; some icon-only buttons lack
  aria-labels (e.g. copy/delete in session view have title but not always aria-label).
- [GAP] No PWA/offline, no push notifications for low attendance alerts.
- [GAP] No audit log of admin actions (create/delete/enroll).
- [GAP] No tests / CI (no test runner configured; build is the only gate).

### Data persistence (deployment risk)
- [GAP] DB is in-memory + `ensureSeeded()` in dev; Cloudflare D1 is the prod store but seeded each cold
  start. Multi-instance / preview deploys reset data. Needs explicit persistence + migration story.
- [GAP] No seed/data-reset admin control.

## Summary of backend-facing changes implied
═══════════════════════════════════════════════════════════════════════════════════
1. New model: `SiteSettings` (institutionName, atRiskThreshold, marqueeItems[], testimonials[],
   demoAccountsEnabled, demoPassword, demoEmailDomain, showFakeStats, primaryColor?, contactEmail?).
2. Extend `Course` with `icon?, color?, category?, description?`; `Department` with `icon?, color?`.
3. New server fns: `getSiteSettings`, `updateSiteSettings` (admin). Extend `createCourse`/`updateCourse`/
   `createDepartment`/`updateDepartment` to accept icon/color.
4. Wire `updateStudent`/`updateLecturer` into admin edit dialogs.
5. Optional: `facultyReport` already exists (`facultyReport` server fn line 430) — add a department
   filter / export UI to use it.
